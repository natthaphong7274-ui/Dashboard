ระบบ: Customer Insight & Performance Tracking Dashboard

ระดับสิทธิ์การเข้าใช้งาน: ผู้อำนวยการระบบ (Director / Administrator)

1. การแนะนำและภาพรวมทุกระบบของโครงการ (Project Subsystems Overview)

1. ระบบฐานข้อมูลเชิงสัมพันธ์บน Google Sheets (Database Subsystem)

  • การทำงาน: ระบบทำงานโดยใช้ Google Sheets เป็นฐานข้อมูลเก็บตารางข้อมูล 10 ชีต (เช่น Users, Tracking, ActivityLog, AI_Followup_Logs ฯลฯ) ข้อมูลยอดขายและชิ้นงานดิบรายวันจะถูกนำเข้าสเปรดชีตนี้เพื่อทำการกรอง ประมวลผล และซิงก์ข้อมูลไปที่หน้าจอผู้ใช้

2. ระบบประมวลผลเซิร์ฟเวอร์หลังบ้าน (Backend Server Subsystem - Google Apps Script)

  • การทำงาน: เซิร์ฟเวอร์ทำหน้าที่ผ่าน V8 Engine ของ Google Apps Script (GAS) โดยรับข้อมูลหรือข้อร้องเรียนจากหน้าบ้านผ่านชุดคำสั่ง google.script.run และทำหน้าที่ดึงข้อมูล ยืนยันสิทธิ์ เขียนประวัติ หรือส่งเรื่องไปประมวลผลภายนอก

3. ระบบรักษาความปลอดภัยและการจำกัดสิทธิ์พื้นที่ (Security & Role-Based Access Control Subsystem)

  • การทำงาน: ตรวจสอบบัญชีด้วยการเข้ารหัส SHA-256 + Salt และจำกัดขอบเขตการดูข้อมูล โดยระดับ Director สามารถเข้าถึงข้อมูลทุกโซนทั่วประเทศพร้อมสิทธิ์การตั้งค่าระบบ ความลับ API และจัดการปลดล็อกผู้ใช้งาน

4. ระบบจัดการแคชข้อมูลความเร็วสูง (High-Performance Caching Subsystem)

  • การทำงาน: เนื่องจากการดึงข้อมูลผู้ประกอบการมีปริมาณมากและขีดจำกัด Google Apps Script แคชต่อชิ้นมีขนาดเพียง 100KB โค้ดหลังบ้านจึงทำระบบบดอัดบีบไฟล์ข้อมูล และแบ่งส่วนออกเป็นชิ้นเล็กๆ (Chunks ละ 25KB) เมื่อเรียกใช้งาน ระบบจะรวมส่วนแคชมาประกอบขึ้นรูป (Reassembly) คืนกลับเป็นออบเจกต์ข้อมูลภายในชั่วพริบตาเพื่อลดความหน่วงหน้าจอ

5. ระบบภูมิสารสนเทศแผนที่อินเทอร์แอคทีฟ (Geospatial Mapping Subsystem - Leaflet.js)

  • การทำงาน: แสดงแผนที่ขอบเขตโซนสีตามระดับคะแนนเกณฑ์ผลงาน (Map Score) วาดขอบเขตผ่านพิกัด GeoJSON มีระบบตรวจจับการชนคิว (Timeout Race Condition) เพื่อรีเซ็ตหน้าจอแผนที่ใหม่อย่างปลอดภัย

6. ระบบแผนภูมิสรุปยอดวิเคราะห์และอันดับ (Visualization Subsystem - Chart.js)

  • การทำงาน: เรนเดอร์กราฟวิเคราะห์แนวโน้มยอดขายสะสม MTD เทียบกับเส้นระดับเป้าหมาย และวิเคราะห์ส่วนแบ่งการตลาดขนส่ง เพื่อเป็นพิกัดให้ AM และ BD ทราบตำแหน่งผลงานรายพื้นที่

7. ระบบวิเคราะห์ปัญญาประดิษฐ์ (AI Insights Engine Subsystem)

  • การทำงาน: ระบบ AI แบบ Multi-Provider Routing สามารถสลับการทำงานไปมาระหว่าง Google Gemini และ OpenAI ได้โดยมีระบบกู้ภัยความผิดพลาด เช่น การวนลูปส่งซ้ำ 3 ครั้งแบบหน่วงเวลา (Exponential Retry Backoff) และฟังก์ชันทำความสะอาดโค้ดมาร์กดาวน์จาก AI (JSON Sanitizer) ป้องกันระบบแชทพัง

8. ระบบผู้ช่วยบอทวิเคราะห์หน้าจอสด (Live Chatbot Assistant Subsystem)

  • การทำงาน: บอทสนทนาที่มุมล่างขวาของแดชบอร์ด มีความสามารถในการอ่านและเก็บค่าบริบทหน้าจอที่ท่านกำลังเปิดอยู่ (Context-Aware) ทำให้บอทสามารถวิเคราะห์ตัวเลขและแผนภูมิที่กำลังแสดงอยู่เพื่อตอบคำถามท่านได้แบบเรียลไทม์

9. ระบบส่งต่อรายงานเมลอัตโนมัติ (Email Dispatcher Subsystem)

  • การทำงาน: ประกอบโครงสร้าง HTML แม่แบบพรีเมียมที่รวบรวมตัวเลขและแผนเจรจาจาก AI ส่งเข้าสู่ระบบอีเมล Gmail ส่วนตัวของ BD ทันทีผ่าน API ของกูเกิลหลังจากท่านกดปุ่มวิเคราะห์

2. บทบาทและหน้าที่หลักของ Director ในระบบ (Director Role Overview)

ในฐานะ ผู้อำนวยการ (Director) ท่านคือผู้ควบคุมดูแลระบบทั้งหมด มีสิทธิ์สูงสุดในการเข้าถึงข้อมูลทั่วประเทศ กำหนดนโยบายเป้าหมาย ประเมินความมั่นคงปลอดภัย และจัดการตัวแปรทางเทคนิคของระบบ AI รวมถึงบริหารจัดการบัญชีผู้ใช้งานพนักงานทั้งหมด ฟังก์ชันการควบคุมระบบของท่านจะประกอบไปด้วย: 1. การดูข้อมูลภาพรวมระดับประเทศแบบครบถ้วนทุกโซน (All Zones View Scope) 2. การกำหนดค่าตัวเลขเป้าหมายเปรียบเทียบผลงานประจำเดือน (Monthly Target Setting) 3. การจัดการสิทธิ์ผู้ใช้งานและปลดล็อกบัญชีพนักงานที่ถูกบล็อก (User Management & Lockout Release) 4. การตั้งค่าสลับเครื่องยนต์ผู้ให้บริการ AI และคีย์ความปลอดภัยระบบ (Advanced AI Engine Configuration) 5. การตรวจสอบประวัติการทำกิจกรรมเชิงสืบสวน (Audit Trail Logs Analysis)

3. การควบคุมเป้าหมายเปรียบเทียบระดับประเทศ (National Target Settings)

3.1 สิทธิ์การคัดกรองระดับประเทศ (All Zones Scope)

ในแผงควบคุมตัวกรองด้านบน ช่อง AREA จะมีตัวเลือกพิเศษคือ "All" ซึ่งระบบจะรวมค่าและดึงไฟล์พิกัด GeoJSON ทั่วประเทศมารวมกันวาดเป็นจุดสีและกราฟเส้นประเมินผลยอดขายเปรียบเทียบพร้อมกันทันที

3.2 การปรับปรุงตัวเลขเป้าหมายเดือนถัดไป (Monthly Target Configuration)

ที่กล่องพริเซนเทชันการ์ดในหน้าหลัก จะมีปุ่ม Action Card สำหรับ "ตั้งเป้าเป้าหมายรายเดือน" 1. คลิกปุ่มตั้งเป้าหมายประจำประเทศ 2. กรอกตัวเลขในแบบฟอร์มภาษาไทย: * เป้าหมายรายได้เฉลี่ยรายวัน (Daily Revenue Target): ค่าเริ่มต้นสำหรับลากเส้นเปรียบเทียบกับยอดขายเฉลี่ยจริงสะสม * เป้าหมายชิ้นงานสะสมประจำเดือน (Monthly Volume Target): ยอดเป้าหมายชิ้นงานขนส่งสะสมของเขตประเทศ 3. กดยืนยันป๊อปอัป ระบบจะนำค่าเหล่านี้ไปอัปเดตลงตัวแปรสภาพแวดล้อมระบบ และอัปเดตเส้นปะเป้าหมายบนกราฟ Chart.js ของพนักงานทุกคนทันทีในวินาทีนั้น

4. ระบบจัดการผู้ใช้และการปลดล็อกบัญชี (User Management & Account Unlock)

4.1 นโยบายการล็อกบัญชีป้องกันการสุ่มเจาะระบบ (Account Lockout Policy)

เพื่อความปลอดภัยสูงสุดของสเปรดชีตองค์กร ระบบหลังบ้านได้รับการพัฒนาให้มีระบบตรวจจับการเข้าสู่ระบบ: * หากผู้ใช้บัญชีใดกรอกรหัสผ่านไม่ถูกต้องติดต่อกันเกิน 5 ครั้ง ระบบหลังบ้านจะนำชื่อบัญชีและข้อมูล IP ดังกล่าวไปเขียนติดสถานะถูกบล็อก (Locked) ใน Script Properties และขัดขวางไม่ให้เข้าระบบทันทีแม้จะกรอกรหัสผ่านที่ถูกต้องในภายหลังก็ตาม

4.2 ขั้นตอนการตรวจสอบและกดยืนยันปลดล็อกพนักงาน (Step-by-step Unlock)

เมื่อได้รับการประสานงานจากเจ้าหน้าที่ BD หรือ AM ว่าบัญชีผู้ใช้ถูกล็อก: 1. คลิกเลือกแท็บเมนูหลัก "🔐 จัดการผู้ใช้" (User Management) 2. ในตารางรายชื่อพนักงาน ให้มองหาพนักงานที่ระบุสถานะสีแดงว่า "Locked" (ถูกล็อก) 3. คลิกปุ่ม "ปลดล็อก" (Unlock) บนแถวข้อมูลของบัญชีนั้น 4. ระบบจะเปิดหน้าจอยืนยันพรีเซนเทชันสีทอง (Lockout Release Confirmation Modal) เพื่อให้ผู้อำนวยการยืนยันตัวตน 5. กดยืนยันปลดล็อก ระบบจะทำการ: * เคลียร์ตัวเลขนับจำนวนประวัติการเดารหัสผ่านผิดพลาด (Password Guess History) ของผู้ใช้รายนั้นกลับไปเป็น 0 * นำสถานะถูกบล็อกออกจากระบบพนักงาน ทำให้บัญชีสามารถกรอกรหัสล็อกอินใหม่ได้ทันที * บันทึกบันทึกประวัติการกระทำลงในประวัติของระบบ (Activity Log) ว่าบัญชีดังกล่าวถูกปลดล็อกโดยผู้อำนวยการคนใด

5. การจัดการตัวแปรสภาพแวดล้อมและสถาปัตยกรรม AI (Settings & AI Provider Setup)

ที่แถบเมนู "⚙️ ตั้งค่าระบบ" (Settings Panel) ท่านสามารถปรับสถาปัตยกรรม AI Engine ได้อย่างไร้รอยต่อ:

5.1 การสลับผู้ให้บริการหลัก (AI_PROVIDER Switch)

  • ในช่องตัวเลือก Active AI Provider ท่านสามารถสลับเลือกระหว่าง Google Gemini และ OpenAI ได้ตามต้องการ
  • เมื่อทำการสลับ ค่าระบบจะเปลี่ยนเส้นทางเรียกใช้ (Endpoint) ไปยังเซิร์ฟเวอร์คลาวด์ของค่ายนั้นโดยอัตโนมัติ

5.2 การใส่คีย์และความเป็นส่วนตัว (API Keys Management)

  • กรอกคีย์ลับที่ช่อง GEMINI_API_KEY หรือ OPENAI_API_KEY
  • สำหรับความปลอดภัยด้านสิทธิ์ข้อมูลและป้องกันการรั่วไหลขณะบันทึกหน้าจอพรีเซนเทชัน ช่องอินพุต OpenAI API Key ได้รับการพัฒนาให้มีสัญลักษณ์รูปดวงตา (Password Visibility Toggle) ผู้อำนวยการสามารถกดไอคอนเพื่อแสดงหรือบดบังข้อมูลตัวอักษรของคีย์ได้

5.3 การระบุรุ่นโมเดลและลำดับสำรอง (Model Defaults & Fallback Chain)

  • ช่องเลือก Dropdown Default Model อนุญาตให้เลือกโมเดลความเร็วสูงราคาประหยัดที่พร้อมให้บริการ (เช่น gemini-2.0-flash, gemini-2.5-flash, gpt-4o-mini, gpt-4o)
  • ในส่วนของ GeminiService.js ระบบสำรองโมเดล (Failover Chain) จะทำหน้าที่อัตโนมัติเมื่อโมเดลหลักโควตาเต็ม โดยข้ามไปยิงเรียกใช้งานโมเดลสำรองถัดไปในรายการที่ตั้งค่าไว้ล่วงหน้าทันที

5.4 ระบบแอนิเมชันปุ่มโหลดความปลอดภัยสูง (Global Loader Timeout Safety)

ทุกครั้งที่กด "บันทึกการตั้งค่าระบบ" (Save Settings) หรือกดยืนยันการปลดล็อกผู้ใช้งาน: * ระบบจะเปิดแอนิเมชัน Global Loader Overlay ซ้อนทับการทำงานทั้งหมดทันที เพื่อความปลอดภัยป้องกันไม่ให้พนักงานกดย้ำส่งคำร้องไปที่กูเกิลเซิร์ฟเวอร์พร้อมกันจนเกิดปัญหา (Race Conditions) * กลไกการกู้ภัยอัตโนมัติ 15 วินาที: เพื่อป้องกันไม่ให้ผู้ใช้งานติดหน้าจอโหลดค้างตลอดชีวิตในกรณีโครงข่ายเชื่อมต่อกูเกิลเซิร์ฟเวอร์ล้มเหลว ระบบโหลดเต็มหน้าจอนี้จะติดตั้งฟังก์ชัน setTimeout ยกเลิกหน้ากาก (Auto-Dismiss) ตัวเองทิ้งภายใน 15 วินาทีทันทีหากเซิร์ฟเวอร์ยังไม่มีการตอบสนองกลับมา

6. การสืบสวนประวัติและกิจกรรมระบบ (Audit Trail Logs Analysis)

ผู้อำนวยการสามารถดึงประวัติการทำกิจกรรมจากชีต ActivityLog เพื่อมาประเมินเหตุการณ์และคัดกรองภัยคุกคามในระบบ โดยข้อมูลที่เก็บบันทึกประกอบด้วย:

  1. Timestamp: วันและเวลาจริงในระดับวินาที
  2. Username & Role: ระบุชัดเจนว่าบัญชีผู้ใช้ใดในฐานข้อมูลระดับสิทธิ์ใดเป็นผู้กระทำกิจกรรม
  3. Action (คีย์คำสั่ง):
    • LOGIN: การเข้าใช้ระบบสำเร็จ
    • LOGIN_FAILED: รหัสผ่านผิดพลาด (ใช้ตรวจสอบการสุ่มรหัสผ่าน)
    • ACCOUNT_LOCKED: บัญชีถูกล็อกเนื่องจากใส่รหัสผิดครบ 5 ครั้ง
    • ACCOUNT_UNLOCKED: ผู้อำนวยการทำการปลดล็อกบัญชีพนักงาน
    • CACHE_REFRESH: การคลิกบังคับดึงข้อมูลจริงจากสเปรดชีต
    • UPDATE_STATUS: การเปลี่ยนสถานะตัวแทนกลุ่มเสี่ยง/เติบโต
    • AI_REQUEST: การประมวลผลร้องขอ Call Script จากปัญญาประดิษฐ์
    • OPEN_CUSTOMER_CARD: การเข้าดึงข้อมูลหรือเปิดดูนามบัตรของลูกค้า (Data Access Log)
  4. Token (Short): ลายนิ้วมือโทเค็นความยาว 8 อักขระสุดท้ายเพื่อใช้ยืนยันกิจกรรมในเซสชันเดียวกัน

6.1 ระบบประวัติการเข้าถึงข้อมูลและการเคลื่อนไหวข้อมูลลูกค้า (AI Access Log & Data Audit Trail)

นอกจากบันทึกการทำงานทั่วไปแล้ว แดชบอร์ดได้เปลี่ยนจากการติดตามสถานะแบบเดิมมาเป็น ระบบการเข้าถึงข้อมูลลูกค้า (Data Access Audit System):

  • ชีตเก็บข้อมูล AI_Followup_Logs: ทุกครั้งที่มีการเปิดหน้าต่างข้อมูลนามบัตรลูกค้า (Customer Card) ระบบจะบันทึก Log ลงชีตนี้โดยอัตโนมัติ โดยระบุสรุปเป็น 🔍 ดึงข้อมูล/ดูนามบัตรลูกค้า เพื่อบันทึกว่า "ใครเรียกดูข้อมูลลูกค้ารายใด ในเวลาใดบ้าง"
  • แท็บวิเคราะห์และติดตามผล AI: ผู้อำนวยการและ AM สามารถติดตามความเคลื่อนไหวเหล่านี้ในตารางประวัติได้ทันที โดยสามารถทำการค้นหาและคลิกหัวคอลัมน์เพื่อจัดเรียงลำดับ (Sort) จากมากไปน้อย หรือน้อยไปมากได้ สะดวกต่อการตรวจดูพฤติกรรมการเรียกดูข้อมูลลูกค้าของทีมงาน

7. คู่มือการแก้ไขปัญหาด้านการดูแลระบบสำหรับผู้อำนวยการ (Technical Troubleshooting)

⚠️ ปัญหาการบันทึก

ตั้งค่า API Key ใหม่และกดบันทึกแล้วขึ้นแถบสีแดงว่าบันทึกล้มเหลว

🔍 สาเหตุหลังบ้าน:
สิทธิ์เข้าถึง Script Properties ของกูเกิลติดขัด หรือโควตาบันทึกของ Script เต็ม
💡 วิธีแก้ไขสำหรับ Director:
ให้เข้าไปอัปเดตค่าความลับผ่านหน้าต่างควบคุมคีย์ (Project Settings) บนกูเกิลคลาวด์ Apps Script หลังบ้านโดยตรง
⚠️ ปัญหาการวิเคราะห์ AI

บอทวิเคราะห์ค้างและหน้าต่างแจ้งโควตาใช้งาน API เต็มอย่างแน่นอน

🔍 สาเหตุหลังบ้าน:
บัญชีผู้ใช้อาจใช้ API Key ของ Free Tier และมีการส่งข้อมูลถี่เกินไป
💡 วิธีแก้ไขสำหรับ Director:
1. ปรับเปลี่ยนผู้ให้บริการ AI กลับเป็นค่ายสำรอง
2. เปลี่ยนประเภทคีย์ API เป็นแบบเรียกเก็บเงินรายเดือน (Pay-as-you-go) บนคอนโซล Google Cloud หรือ OpenAI
⚠️ ปัญหาระบบช้า

ตารางข้อมูลในระบบโหลดช้าอย่างมาก

🔍 สาเหตุหลังบ้าน:
ขนาดไฟล์ประวัติรายชิ้นสะสมมีขนาดเกินขีดจำกัด 100KB
💡 วิธีแก้ไขสำหรับ Director:
แดชบอร์ดจะแบ่งเก็บข้อมูลแบบ Chunks (25KB/ชิ้น) หากข้อมูลโตเกินไป ให้เข้าไปล้างแคชโดยกดปุ่ม 🔄 รีเฟรช หรือเคลียร์แถวประวัติที่เสร็จสิ้นแล้วย้ายไปเก็บที่ชีต Archive ย้อนหลัง
⚠️ ปัญหาการกรองข้อมูล

มีรายงานบั๊กการกรองข้อมูลพนักงานข้ามพื้นที่รับผิดชอบ

🔍 สาเหตุหลังบ้าน:
ข้อมูลการจับคู่ Zone หรือสิทธิ์พนักงานในชีต Users ขัดแย้งกัน
💡 วิธีแก้ไขสำหรับ Director:
เข้าไปเปิดไฟล์สเปรดชีตฐานข้อมูล เช็กคอลัมน์ Zones ของพนักงานคนนั้น หากต้องการให้มองเห็นได้หลายโซนให้พิมพ์คั่นด้วยคอมม่า เช่น Zone 1, Zone 2 และเว้นวรรคให้ถูกต้องตามหลักฐานข้อมูล
